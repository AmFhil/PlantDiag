[CRIT-01] Non-Direct ByteBuffer in TFLiteInterpreterPlugin.java (Android JNI Crash)
--------------------------------------------------------------------------------
- Location: Agrinovva mobile app/android/app/src/main/java/com/naijaharvest/app/TFLiteInterpreterPlugin.java (line 59)
- Description: In runInference(), input bytes are wrapped using:
  ByteBuffer inputBuffer = ByteBuffer.wrap(inputBytes).order(ByteOrder.LITTLE_ENDIAN);
- Flaw: In Android TensorFlow Lite JNI, Interpreter.run() uses env->GetDirectBufferAddress().
  Calling this on a non-direct ByteBuffer (heap-backed array) returns NULL or throws
  java.lang.IllegalArgumentException: The buffer is not a direct buffer.
- Impact: Inference will crash or throw an unhandled exception immediately upon photo capture on native Android.
- Fix: Allocate a direct ByteBuffer:
  ByteBuffer inputBuffer = ByteBuffer.allocateDirect(inputBytes.length).order(ByteOrder.LITTLE_ENDIAN);
  inputBuffer.put(inputBytes);
  inputBuffer.rewind();

[CRIT-02] Severe Heap Allocation Spike & Out-Of-Memory (OOM) Risk in Model Loading
--------------------------------------------------------------------------------
- Location: Agrinovva mobile app/android/app/src/main/java/com/naijaharvest/app/TFLiteInterpreterPlugin.java (lines 78-85)
- Description: loadModel() uses readAllBytes(is) via ByteArrayOutputStream to load the
  44.8 MB .tflite model into a Java heap byte[] before copying to a direct ByteBuffer.
- Flaw: The ByteArrayOutputStream resizes dynamically (allocating 16MB -> 32MB -> 64MB buffers),
  spiking JVM heap allocation by over 120-150 MB during model loading.
- Impact: Target devices in rural Nigeria are low-spec Android phones with 2GB RAM.
  This triggers an OutOfMemoryError and kills the application on startup or inference.
- Fix: Use zero-copy memory-mapped I/O via AssetFileDescriptor:
  AssetFileDescriptor afd = getContext().getAssets().openFd(MODEL_ASSET);
  FileInputStream fis = new FileInputStream(afd.getFileDescriptor());
  FileChannel channel = fis.getChannel();
  MappedByteBuffer buffer = channel.map(FileChannel.MapMode.READ_ONLY, afd.getStartOffset(), afd.getDeclaredLength());
  interpreter = new Interpreter(buffer);

[CRIT-03] SQLite Connection Crash on Activity Resume / Screen Rotation
--------------------------------------------------------------------------------
- Location: Agrinovva mobile app/src/js/database.js (lines 148-158)
- Description: initDB() creates a new SQLite connection with plugin.createConnection()
  whenever the JS memory variable _db is null.
- Flaw: When an Android activity pauses/resumes, rotates, or reloads the WebView, _db is null
  in JS, but the native SQLite plugin retains the open connection in memory. Calling
  plugin.createConnection() throws: "Connection naijaharvest already exists".
- Impact: The catch block sets _db = null. From that point onwards, all database operations
  (farmer registration, diagnosis history) permanently fail for the remainder of the session.
- Fix: Check plugin.isConnection({ database: DB_NAME }). If true, call
  plugin.retrieveConnection({ database: DB_NAME }). Otherwise call createConnection().

[CRIT-04] Farmer Profile Update Permanently Orpans / Deletes Historical Diagnoses
--------------------------------------------------------------------------------
- Location: Agrinovva mobile app/src/js/database.js (lines 245-285)
- Description: saveFarmer() generates a new UUID() on every invocation. When saving a farmer
  with an existing NIN, the SQL query executes INSERT OR REPLACE INTO farmers.
- Flaw: Because NIN is UNIQUE, SQLite deletes the old farmer row and inserts a new row with
  the NEW id. In the schema, the diagnoses table defines:
  FOREIGN KEY (farmer_id) REFERENCES farmers (id) ON DELETE SET NULL.
- Impact: Every time an extension agent updates a farmer's details (phone, village, etc.),
  SQLite's foreign key cascade automatically overwrites farmer_id = NULL on ALL past diagnoses
  for that farmer, permanently destroying the link between farmers and historical data.
- Fix: Before inserting, check if a farmer with the given NIN already exists in SQLite.
  If found, preserve their existing id rather than generating a new UUID.

[HIGH-01] "Green-Pixel" Preprocessing Gate Rejects Real Crop Diseases
--------------------------------------------------------------------------------
- Location: Agrinovva mobile app/src/js/diagnosis.js (lines 101-114, 234-247)
- Description: validatePlantImage() requires at least 8% of pixels to satisfy:
  g > r + 30 && g > b + 20 && g > 60
- Flaw: Severe crop diseases (Apple Cedar Rust, Orange Citrus Greening, Grape/Apple Black Rot,
  Potato/Tomato Early & Late Blight, Tomato Yellow Leaf Curl) produce yellow, orange, brown,
  or black necrotic tissue where red and green are equal or red dominates green.
- Impact: If a farmer takes a close-up photo of a diseased or necrotic leaf, it has 0%
  bright-green pixels. The app erroneously rejects valid diseased crops with:
  "Not a plant image — Please capture a clear photo of a crop leaf or stem."
- Fix: Expand foliage detection heuristic to include chlorotic yellow and necrotic brown tones:
  - Green: (g > r + 15 && g > b + 10 && g > 40)
  - Yellow: (r > 90 && g > 90 && b < 110 && Math.abs(r - g) < 40)
  - Brown/Rust: (r > 50 && g > 30 && b < 70 && (r - b) > 15)

[HIGH-02] Softmax Temperature (1.5) Inflates Entropy and Causes False Rejections
--------------------------------------------------------------------------------
- Location: Agrinovva mobile app/src/js/diagnosis.js (lines 51-53, 250-260)
- Description: SOFTMAX_TEMPERATURE is set to 1.5. Output logits are divided by 1.5 before softmax.
  Then normalized entropy is compared against ENTROPY_REJECT_THRESHOLD = 0.72.
- Flaw: Temperature division flattens probability across 38 classes, directly inflating
  Shannon entropy.
- Impact: Models with a clear top prediction before scaling exceed the 0.72 entropy threshold
  and get falsely rejected with: "Image too unclear — Try better lighting".
- Fix: Set SOFTMAX_TEMPERATURE = 1.0 or calibrate ENTROPY_REJECT_THRESHOLD to 0.82.

[HIGH-03] Diagnoses are Never Associated with Farmers in UI or Database

- Fix: Add an optional "Select Farmer" dropdown on the Diagnose screen, populating it with
  registered farmers from getFarmers(), and pass the selected farmerId to saveDiagnosis().

[HIGH-04] Corrupted Photo Evidence in Agent Tools (Truncated to 20,000 Chars)
