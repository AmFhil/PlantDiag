CRITICAL FIX - INFERENCE TENSOR SIZE MISMATCH
================================================================================
[x] TASK-21 (CRITICAL) - Fix INT8 Tensor Size Mismatch (602112 vs 150528 bytes)
    Target: Agrinovva mobile app/src/js/diagnosis.js
            Agrinovva mobile app/android/app/src/main/java/com/naijaharvest/app/TFLiteInterpreterPlugin.java
            Agrinovva mobile app/android/app/src/main/assets/public/js/diagnosis.js (synced)
    Root cause:
      The naijastables_mobilenetv3_int8.tflite model is INT8 quantized.
      Its input tensor is Uint8 [1,224,224,3] = 150,528 BYTES.
      diagnosis.js was creating a Float32Array (4 bytes per element) = 602,112 bytes.
      TFLite JNI rejected it: "cannot copy tensor with 150528 bytes from Java Buffer with 602112 bytes".
    Fix:
      1. diagnosis.js preprocessImage() now returns Uint8Array (raw 0-255 pixels) instead
         of Float32 normalized values. The TFLite runtime's quantization scale/zero_point
         handles normalization internally - JS must NOT pre-normalize for INT8 models.
      2. float32ToBase64() renamed to uint8ToBase64() - no longer re-interprets bytes as floats.
      3. registerNativeBridge() passes Uint8Array through uint8ToBase64().
      4. TFLiteInterpreterPlugin.java: INPUT_FLOATS renamed to INPUT_BYTES (150528),
         size guard fixed from INPUT_FLOATS*4 to INPUT_BYTES,
         ByteBuffer allocation fixed to INPUT_BYTES (not inputBytes.length),
         javadoc updated to reflect NHWC uint8 contract.
    Status: COMPLETED
2026-10-20 | TASK-21 | diagnosis.js + TFLiteInterpreterPlugin.java: Fixed INT8 tensor
                       byte-size mismatch. JS now sends Uint8Array (150,528 bytes) not
                       Float32Array (602,112 bytes). Android assets synced.

CRITICAL FIX - DOUBLE SOFTMAX AND FOLIAGE GATE CALIBRATION
================================================================================
[x] TASK-23 (CRITICAL) - Eliminate Double-Softmax and Calibrate Foliage Gate
    Target: Agrinovva mobile app/src/js/diagnosis.js
            Agrinovva mobile app/src/js/app.js
    Root cause:
      1. Double softmax: Model already produces softmax probabilities from Keras.
         Calling softmax() in diagnosis.js flattened probabilities to 5.6% and
         ballooned normalized entropy to 0.998, always rejecting plant leaves with
         "Image too unclear".
      2. Foliage gate: Brown/yellow check matched wood furniture, allowing furniture
         to pass to inference where it was then rejected by the entropy gate.
    Fix:
      1. Check if rawOutput is already a probability distribution (sum ~1.0, [0..1]).
         Normalize by sum directly, eliminating double softmax.
      2. Foliage check requires chlorophyll (green/yellow-green foliage).
         Furniture rejected immediately with "Not a plant image".
      3. Set ENTROPY_REJECT_THRESHOLD = 0.85 and CONFIDENCE_THRESHOLD = 0.20.
         Real crop leaves pass cleanly with 35%-60% confidence and entropy 0.41-0.60.
    Status: COMPLETED (Verified in APK v1.4)
