# Naija Harvest Offline App - Product PRD, Architecture & Plan

---

## 📋 PRODUCT PRD (Product Requirements Document)

### 1. Executive Summary

**Product Name:** Naija Harvest Offline

**Vision:** Bridge the last-mile digital divide for Nigeria's smallholder farmers through an offline-first, voice-enabled Android app that provides instant crop diagnosis and advisory in local languages.

**Target Users:**
- **Primary:** Extension agents (7,000 public agents, 35-70M farmers served)
- **Secondary:** Smallholder farmers with feature phones (SMS/USSD layer)
- **Tertiary:** Unemployed youth (Digital Extension Assistants)

**Core Value Proposition:**
- Instant offline crop disease diagnosis using AI
- Voice output in Hausa, Yoruba, Igbo, and Nigerian Pidgin
- No internet required
- No additional hardware needed
- Aligned with NDFR and government extension systems

---

### 2. Problem Statement

| Metric | Current State | Target State |
|--------|--------------|--------------|
| Extension ratio | 1:5,000-10,000 | 1:800 (FAO recommendation) |
| Yield loss to pests | 22.5% annually | <10% |
| Diagnosis time | Days to weeks | <1 minute |
| Language barrier | English-only | 4 Nigerian languages |
| Internet dependency | Required | Completely offline |

**User Pain Points:**
- Farmers wait days for agent visits
- Agents overwhelmed with 5,000+ farmers
- Youth lack structured entry into agriculture
- No trusted intermediary between observation and expert advice

### 2. Component Architecture

#### Component A: Image Capture & Processing

```
User takes photo → Camera Plugin → Resize to 224x224 → NCHW + ImageNet normalize → Native TFLite Interpreter
```

**Input:** Photo from camera (JPEG data URL via @capacitor/camera)
**Processing:** Canvas resize to exactly 224x224 (stretch), RGBA→RGB, 0–1 scale,
channels-first NCHW layout, ImageNet mean/std normalization
**Output:** Float32Array of 150528 floats (1×3×224×224) → passed to the native bridge

#### Component B: ML Inference Pipeline

```
Camera Image → Preprocessing → Native TFLite Model → Post-processing → Diagnosis Result
```

**Model:** ResNet18 (PlantVillage-trained, ai-edge-torch → TFLite Float32, 42.73 MB)
**Classes:** 38 disease classes across 14 crops
**Bridge:** WebView → `window.NaijaHarvestDiagnosis.runInference(Float32Array(150528))`
  → native Java TFLite Interpreter (`Interpreter.run` on the NCHW input) → resolves
  `Promise<Float32Array(38)>` of raw logits. Absent in plain-browser preview mode;
  diagnosis rejects with a clear "Native TFLite runtime not available" message.
**Post-process (WebView, browser-testable):** softmax with temperature 2.0, top-3
  ranked, filtered at probability ≥ 0.3, normalized entropy as certainty gauge.
**Confidence Threshold:** ≥ 30% probability (softmax temp 2.0) for display

#### Component C: Voice Output Pipeline

```
Diagnosis Text → Template Match → Pre-generated Audio Clip (Tier 1)
                → Fallback: Android Native TTS (Tier 2)
                → Fallback: Cloud TTS + Cache (Tier 3, online only)
```

**Languages:** English, Hausa, Yoruba, Igbo, Pidgin
**Output:** Spoken diagnosis + treatment advice (pre-generated MP3/Opus clips)
**Fallback:** Android native TTS (English or ha/ig/yo where available) if clip missing

## 📦 TECHNICAL SPECIFICATIONS

### PlantVillage Model Details (VALIDATED Aug 2026)

| Parameter | Value |
|-----------|-------|
| **Model Architecture** | ResNet18 (PyTorch, ai-edge-torch → TFLite) |
| **Input Size** | 224x224x3, Float32, **NCHW (channels-first)** |
| **Output** | Float32 [1, 38] logits (PlantVillage 38 classes) |
| **Normalization** | ImageNet mean [0.485, 0.456, 0.406], std [0.229, 0.224, 0.225] (0–1 scaled pixels) |
| **Classes** | 38 (14 crops) |
| **Format** | TFLite (all builtin ops: TRANSPOSE, PAD, PADV2, CONV_2D, MAX_POOL_2D, ADD, SUM, FULLY_CONNECTED — no custom/Flex ops) |
| **Quantization** | None (Float32) — no quality loss |
| **Approx Size** | 42.73 MB (measured from the actual downloaded file) |
| **Source** | `Aleksandra1104/Plant-Disease-Detector` v1.0.0 release (github.com/Aleksandra1104/Plant-Disease-Detector) |
| **Runtime** | Native TFLite Java (`org.tensorflow:tensorflow-lite`) — tfjs-tflite (WASM) was tested and REJECTED ("Can't initialize model": 2022 schema vs 2025 ai-edge-torch model) |
| **Postprocess** | softmax temperature 2.0, top-3 filtered at confidence ≥ 0.3, normalized entropy (0–1) as certainty gauge |

## 🔬 FEASIBILITY FINDINGS (Validated Aug 2026)

> **STATUS: On-device SoroTTS is NOT FEASIBLE on target hardware. Architecture revised below.**

### 1. On-Device SoroTTS (Orpheus-3B) — Verdict: REJECTED

**Empirical benchmark (llama.cpp b10507, i5-7200U laptop CPU = low-end phone proxy):**

| Measurement | Value |
|-------------|-------|
| Qwen2.5-0.5B Q4_K_M (463 MiB) generation | 20.01 tok/s |
| Orpheus-3B Q4_K_M (1996 MiB) predicted | ~4.6 tok/s (bandwidth-scaled) |
| Audio tokens per second of speech (SNAC: 7 codes/12ms frame) | ~583 |
| Real-time factor on laptop CPU | ~127x (1s speech = 127s compute) |
| Real-time factor on 2GB-RAM phone (2-5x slower) | ~250-600x |
| **Time to speak a 10-second diagnosis on phone** | **40-100 minutes** |
| Model working set (weights + KV + buffers + Chaquopy) | ~2.3-2.5 GB |
| Available RAM on 2GB phone | ~0.8-1.2 GB |

**Fatal blockers:**
1. **Memory**: The 2GB model file alone exceeds total device RAM. Cannot load.
2. **Speed**: 250-600x real-time factor makes voice output unusable (PRD target: <30s diagnosis).
3. **Pidgin missing**: SoroTTS covers Hausa, Yoruba, Igbo — but NOT Nigerian Pidgin (20 languages listed in model card). The "4 languages" claim is false for this model.
4. **No native Android path**: llama.cpp Orpheus support (issue #12476) still open since Mar 2025; only community fork TTS.cpp has basic support. Chaquopy + 3B LLM on Android: no production evidence exists.
5. **Battery/thermals**: Sustained 2-3 GB weight streaming on phone SoC would overheat and drain a battery in under an hour.

### 2. Piper TTS — Rejected for Nigerian languages

Piper is ideal *in principle* (15M params, real-time on Raspberry Pi, fully offline CPU).
**But the official voice catalog has NO Hausa, Yoruba, Igbo, or Pidgin voices.** No pre-trained Nigerian-language Piper models exist to download.

### 3. What Works — Recommended Voice Architecture (REVISED)

```
┌──────────────────────────────────────────────────────────────────┐
│                      VOICE OUTPUT LAYER (v2)                    │
│                                                                  │
│  TIER 1: Pre-Generated Audio Library (OFFLINE, PRIMARY)         │
│  ┌────────────────────────────────────────────────────────────┐  │
│  │  Diagnosis phrases are a FINITE set:                      │  │
│  │  38 diseases × ~5-10 template phrases × 5 languages       │  │
│  │  ≈ 1,875 audio clips, pre-synthesized at build time       │  │
│  │  via cloud TTS (9jaLingo / Orinode / Azure), bundled      │  │
│  │  as MP3/Opus assets (~10-20 MB per language).             │  │
│  │  Playback = instant, zero compute, zero RAM, 100% offline │  │
│  └────────────────────────────────────────────────────────────┘  │
│                                                                  │
│  TIER 2: Android Native TTS (OFFLINE, FALLBACK)                 │
│  ┌────────────────────────────────────────────────────────────┐  │
│  │  android.speech.tts for dynamic text (farmer name,        │  │
│  │  free-form notes). Check isLanguageAvailable(ha/ig/yo)    │  │
│  │  at runtime; fall back to Nigerian-accented English.      │  │
│  │  Pidgin has NO native Android TTS support.                │  │
│  └────────────────────────────────────────────────────────────┘  │
│                                                                  │
│  TIER 3: Cloud TTS On-Demand (ONLINE, OPTIONAL)                 │
│  ┌────────────────────────────────────────────────────────────┐  │
│  │  When online: 9jaLingo API (ha/ig/yo/pcm, Apache-2.0,     │  │
│  │  voice cloning) or Orinode (₦0.20/char) synthesize        │  │
│  │  free-form text → cache result locally for reuse.         │  │
│  └────────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────────┘
```

**Key insight:** Crop diagnosis output is *template-based*, not free-form. A farmer hears "This is Fall Armyworm. Treat with [X] within 7 days." — that's a finite set of phrases. Pre-generating them eliminates the on-device TTS problem entirely.

**Estimated asset sizes (Tier 1):**
- 16 kHz MP3/Opus, ~10-30 KB per 5-10s clip
- 1,875 clips ÷ 5 languages ≈ 375 per language ≈ 5-15 MB per language
- All 5 languages bundled ≈ 25-75 MB — acceptable for offline-first app
  (English set can ship first / be optional if storage is tight)

### 5. Changes to PRD

1. **Remove**: Chaquopy, SoroTTS, Orpheus-3B, Python runtime, `android/python/`, `models/soro_tts/`
   (~2GB), TTS Cordova plugin. → Migrated to Capacitor: `@capacitor/camera`, `@capacitor-community/sqlite`,
   Web Audio for playback. Native layer is now only a thin TFLite + TTS wrapper.
2. **Keep**: PlantVillage ResNet18 TFLite diagnosis (42.73 MB Float32 — perfectly feasible, validated; larger than the earlier 5-10 MB MobileNetV2 estimate but still installs offline and runs in ~100-200ms on modern devices).
3. **Add**: Audio asset pipeline (Tier 1), Android native TTS fallback, cloud TTS integration (Tier 3).
4. **Defer**: On-device neural TTS to "future" — revisit only if a Kokoro-scale (<100M params) Nigerian-language model appears. **Reference point: user's AfriTutorAi project already runs Kokoro-82M (89 MB, real-time CPU) via onnxruntime — that is the right scale class; no Nigerian-language equivalent exists yet.**

### 11. Nigerian Staple Crop Model Roadmap (Phases 5 & 6)

While the initial model release leverages the 38-class PlantVillage dataset (covering Tomato, Potato, Corn, Pepper, Apple, Grape), Nigerian agricultural security is primarily anchored on staple root and tuber crops:

1. **Makerere AI Lab / IITA Cassava Disease Dataset:**
   - Diseases: Cassava Brown Streak Disease (CBSD), Cassava Mosaic Disease (CMD), Cassava Bacterial Blight (CBB), Cassava Green Mite (CGM).
   - Target: Fine-tune MobileNetV3 / ResNet18 backbone using transfer learning on ~15,000 field-collected Ugandan and Nigerian leaf images.
2. **IITA Yam Pathology Dataset:**
   - Diseases: Yam Anthracnose (*Colletotrichum gloeosporioides*), Yam Mosaic Virus (YMV), Yam Leaf Blight.
3. **Cowpea & Sorghum Extension Models:**
   - Pests & Pathogens: Maruca pod borer, Cowpea Cercospora leaf spot, Sorghum Anthracnose.
4. **Model Quantization Target:**
   - Full post-training INT8 quantization via TFLite converter to reduce model footprint from 44.8 MB down to ~11-14 MB, drastically speeding up inference to <150ms on MediaTek Helio G25/G35 budget devices.
