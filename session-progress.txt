WHAT THE APP IS
================================================================================
AgriNovva is an OFFLINE crop disease diagnosis Android app for Nigerian smallholder
farmers. It works with ZERO internet access.

Key features:
  - Take a photo of a plant leaf -> AI diagnoses the disease in < 85ms
  - Voice advisory in 5 Nigerian languages: English, Hausa, Yoruba, Igbo, Pidgin
  - Disease treatment advice from local disease database (disease_db.json)
  - Farmer registration and field visit records (SQLite, offline)
  - Agent tools for agricultural extension officers
  - Full offline sync queue for when connectivity is restored

AI Model: MobileNetV3-Large INT8 quantized TFLite
  - 30 Nigerian staple crop disease classes (NaijaStaples-30)
  - Cassava (5), Maize (4), Yam (3), Cowpea (3), Rice (4),
    Tomato (6), Pepper (3), Sorghum (2)
  - ~5MB on disk, ~12MB RAM, 45-85ms on Helio G25/G35

[DONE] TASK-21 - CRITICAL: Fix INT8 tensor size mismatch (602112 vs 150528 bytes)
       Files:
         src/js/diagnosis.js
         android/app/src/main/java/com/naijaharvest/app/TFLiteInterpreterPlugin.java
         android/app/src/main/assets/public/js/diagnosis.js (synced)

       ERROR MESSAGE THAT WAS HAPPENING:
         "Inference failed: cannot copy a TensorFlowLite tensor
          (serving_default_input_image_:0) with 150528 bytes from a
          Java Buffer with 602112 bytes."

       ROOT CAUSE:
         The model (naijastables_mobilenetv3_int8.tflite) is INT8 quantized.
         Its input tensor is: Uint8 [1, 224, 224, 3] = 150,528 BYTES.
         But diagnosis.js was building a Float32Array -> 150,528 floats x 4 bytes
         = 602,112 bytes. The TFLite JNI rejected it (4x size mismatch).

       FIX - diagnosis.js:
         BEFORE: Float32Array, pixel values normalized to [-1, 1]
         AFTER:  Uint8Array, raw pixel values 0-255 (RGB, NHWC)
         WHY:    INT8 models store normalization as quantization scale/zero_point
                 inside the .tflite flatbuffer. The runtime applies it internally.
                 JS must NOT pre-normalize - send raw uint8 pixels only.
         Changes:
           - preprocessImage() -> now returns Uint8Array (raw pixels, no division)
           - float32ToBase64() -> renamed to uint8ToBase64() (no Float32 recast)
           - registerNativeBridge() -> passes uint8ToBase64(inputTensor)
           - All JSDoc and contract comments updated

       FIX - TFLiteInterpreterPlugin.java:
         BEFORE: INPUT_FLOATS = 150528, size check = INPUT_FLOATS * 4 = 602112
                 ByteBuffer.allocateDirect(inputBytes.length)  [= 602112]
         AFTER:  INPUT_BYTES = 150528, size check = INPUT_BYTES = 150528
                 ByteBuffer.allocateDirect(INPUT_BYTES)  [= 150528]
         Changes:
           - INPUT_FLOATS -> INPUT_BYTES = 1 * 224 * 224 * 3
           - Size guard: inputBytes.length < INPUT_BYTES
           - ByteBuffer.allocateDirect(INPUT_BYTES)  [exact fit]
           - inputBuffer.put(inputBytes, 0, INPUT_BYTES)  [safe bounded put]
           - Javadoc updated: NHWC uint8 contract documented

[DONE] TASK-22 - CRITICAL: Fix UINT8 output tensor type mismatch
       Files:
         android/app/src/main/java/com/naijaharvest/app/TFLiteInterpreterPlugin.java

       ERROR MESSAGE:
         "Inference failed: cannot convert between a TensorFlow Lite tensor
          with type UINT8 and a Java object of type [F (which is compatible
          with TensorFlow Lite type FLOAT32)"

       ROOT CAUSE:
         INT8 quantized models have UINT8 output tensors (not FLOAT32).
         Java notation [F = float[] (single-bracket array of floats).
         The code was passing float[][] output to interpreter.run() but
         TFLite CANNOT auto-cast its UINT8 output into a Java float[].

       FIX:
         BEFORE: float[][] output = new float[1][numClasses];
                 interpreter.run(inputBuffer, output);
                 for (float v : output[0]) logits.put(v);

         AFTER:  byte[][] rawOutput = new byte[1][numClasses];
                 interpreter.run(inputBuffer, rawOutput);
                 // Read quantization params from tensor metadata
                 float scale = outTensor.quantizationParams().getScale();
                 int zeroPoint = outTensor.quantizationParams().getZeroPoint();
                 // Dequantize: (uint8_value - zero_point) * scale
                 for (byte b : rawOutput[0]) {
                     float dequantized = ((b & 0xFF) - zeroPoint) * scale;
                     logits.put(dequantized);
                 }

         NOTE: (b & 0xFF) is critical - Java byte is signed (-128..127) but
               UINT8 is unsigned (0..255). The mask restores the unsigned value.

         Also added: import org.tensorflow.lite.Tensor;
         Also added: Log.d output tensor shape/scale/zeroPoint for debugging.

[DONE] TASK-23 - CRITICAL: Fix double-softmax flattening and false foliage detection
       Files:
         Agrinovva mobile app/src/js/diagnosis.js
         Agrinovva mobile app/src/js/app.js (bumped cache buster to ?v=4)

       ERROR SYMPTOM:
         "Image too unclear: Try better lighting and hold the camera steady closer to the leaf"
         on both plant leaves and furniture.

       ROOT CAUSE 1 (DOUBLE SOFTMAX):
         The Keras model architecture already ends in:
           layers.Dense(num_classes, activation="softmax")
         When quantized to INT8, the output tensor scale is 0.00390625 (= 1/256),
         meaning Java dequantized output: (uint8_byte & 0xFF) * scale
         is ALREADY the direct softmax probability [0..1]!
         In diagnosis.js, passing these probabilities through softmax() a SECOND time
         squashed top probabilities from 55% down to 5.6%, producing a flat, near-uniform
         distribution with normalized entropy 0.998.
         Because 0.998 > ENTROPY_REJECT_THRESHOLD, Gate 2 ALWAYS rejected valid plant leaves
         with "Image too unclear"!

       ROOT CAUSE 2 (FURNITURE FOLIAGE DETECTION):
         validatePlantImage() previously included brown/yellow thresholds that matched
         wood grain and tan furniture, passing furniture to inference where it then also
         hit the double-softmax entropy gate.

       FIX:
         1. diagnosis.js: Detect if rawOutput is already a normalized probability
            distribution (sum in [0.7, 1.3], values in [0, 1]). Normalize by sum directly,
            preventing double softmax.
         2. Foliage detection: Require active chlorophyll (photosynthetic green or
            chlorotic yellow-green where green is strong). Real leaves have >= 13.9%
            plant pixels, wood/furniture has < 1%. Threshold set to 4% (0.04).
         3. Calibrated ENTROPY_REJECT_THRESHOLD = 0.85 and CONFIDENCE_THRESHOLD = 0.20.
            Cassava and maize leaves tested directly yield 35%-57% confidence and
            entropy 0.41-0.60, passing cleanly!
